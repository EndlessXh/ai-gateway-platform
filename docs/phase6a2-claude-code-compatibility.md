# Phase 6A.2 — Claude Code native compatibility

**Status:** technical closure complete; production release remains blocked

**Date:** 2026-07-31

**Branch:** `feature/phase6a2-claude-code-compat`

## Outcome

The official Claude Code 2.1.220 native executable completed a real minimal
request through `Claude Code → HYC AI /v1/messages → OpenRouter →
anthropic/claude-opus-4.6`. The client used only the public
`claude-opus-4.6` alias. The final live run exited zero, created one HYC usage
log, exposed no upstream identity, and added `$0.0000000` to the measured
OpenRouter account usage.

The project launcher is `scripts/run-claude-code-hyc.ps1`. It reads only
`HYC_API_BASE_URL`, `HYC_API_TOKEN`, and `HYC_PUBLIC_MODEL` from a local env
file, invokes the official native executable directly, sets gateway variables
only on the child process, and never changes a PowerShell profile, CC Switch,
Claude global settings, or User/Machine environment variables. It rejects an
OpenRouter base URL and never receives an OpenRouter key.

## Reproduction and root cause

Claude Code added these structural fields compared with the earlier minimal
Messages probe: three system blocks, `metadata`, `context_management`, prompt
cache controls, a 32K default output ceiling, default SSE, and—outside minimal
mode—26 tools plus an enabled thinking budget. Only structure was captured;
credentials, header values, prompts, tool arguments, response bodies and
request/session identifiers were not recorded. The ignored comparison is at
`artifacts/phase6a2-claude-code/request-shape-comparison.json`.

The failure occurred at layer A, HYC request validation, before model mapping,
Messages conversion, OpenRouter serialization, network I/O, usage settlement,
or logging. Each request was rejected in 3–12 ms with the diagnostic class:

`routing control field "metadata" is not allowed`

Claude Code retried those immediate HTTP 500 responses with backoff, making the
failure appear to take roughly three minutes. OpenRouter returned no error and
charged nothing.

The Phase 6A.1 privacy guard treated `metadata` as an OpenRouter routing
control for every input format. That is correct for OpenAI-compatible inputs,
where user metadata must not influence the upstream route, but incorrect for
Anthropic Messages: Claude Code legitimately sends Anthropic client metadata.
The Claude-to-OpenAI converter already drops that field, so rejecting it did
not add privacy protection.

The fix is format-scoped: Anthropic Messages may contain `metadata`, and that
value is discarded before the OpenRouter request. OpenAI/Responses metadata
and `provider`, `route`, `models`, `fallbacks`, `plugins`, `transforms`,
`debug`, `trace`, and `session_id` remain forbidden routing controls.

## Header and field policy

- `Authorization` and `x-api-key` are accepted Anthropic credential forms. If
  both are present and differ, HYC returns 401 instead of silently preferring
  one credential.
- Client credentials, cookies, Claude session headers, Stainless headers,
  `anthropic-beta`, and application identity headers are not forwarded by the
  OpenRouter adapter. The channel-owned Authorization header is generated by
  HYC.
- `anthropic-version` and Claude Code beta headers are accepted at the HYC
  protocol boundary; no client beta value is blindly forwarded upstream.
- Public model mapping, system content, tools, tool results, cache controls,
  thinking/reasoning, stop sequences, streaming and content blocks retain
  their existing semantic conversion.
- Claude `tool_choice` now maps `auto`, `any`, `none`, named tools, and
  `disable_parallel_tool_use` to the corresponding OpenAI-compatible fields.
- Claude `metadata` and `context_management` are client-only and are not sent
  to OpenRouter.

The launcher caps `CLAUDE_CODE_MAX_OUTPUT_TOKENS` at 4096. Minimal probes also
disable thinking; normal project runs retain thinking with a 1024-token bound.
These child-only limits prevent a short check from silently becoming a 32K
reasoning request. They are safeguards, not the root fix.

## Error behavior

Buffered upstream 400, 401, 402, 403, 408, 422, 429, 502, and 503 statuses keep
their status instead of becoming 500. Terminal OpenRouter errors delivered
inside an HTTP-200 stream are sanitized and converted to Anthropic
`event: error` events (`rate_limit_error`, `overloaded_error`, or `api_error`).
Provider messages, URLs, slugs, channel IDs, and generation/request IDs are
not exposed. Returning a terminal stream error marks the relay failed, skips
retry, refunds pre-consumption and avoids appending an invalid JSON error after
SSE has started.

The zero-cost local regression creates a run-scoped SQLite gateway and a
loopback OpenRouter-shaped stub. It now invokes the actual Claude executable
through HYC and asserts that client metadata is absent from the converted
request while `data_collection=deny`, `zdr=true`, and
`require_parameters=true` remain enforced.

## Boundaries and blockers

Cursor remains a protocol-only conclusion: standard OpenAI Chat Completions
buffered/SSE/tools/errors/cancellation are verified, but the Cursor application
body is unverified. No user Cursor setting was changed, and the product must say
“compatible with standard OpenAI Chat Completions clients,” not claim native or
complete Cursor support.

Production sale is still fail-closed. `SOURCE_CODE_URL` is empty and requires
the owner to publish the exact corresponding source at a real HTTPS location.
`PRICING_STATUS=provisional` requires a human commercial decision. Production
nginx/DNS/TLS/egress verification also remains outstanding. Phase 6B has not
started; no multi-upstream, multi-account, regional failover, production
deployment, UI, or pricing implementation is included here.
